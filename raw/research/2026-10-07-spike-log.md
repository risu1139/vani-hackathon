## Voice Agents SDK, CALL mode (spikes 2, 3, 4, 7), 2026-10-07 ~09:00–09:08
- A separate Voice Agents key (Indus → Deploy with code → Generate API key) fixes the 401. CHAT mode → 404 "App not found for the interaction type"; **CALL mode with version=1 works.**
- Harness: Sarvam TTS (bulbul:v3, speaker "rahul", 16 kHz) plays the seller; the agent is Shubh; continuous 20 ms PCM frames; agent speech detected by RMS > 700 (background "Quiet office" ambience streams constantly: p50 RMS ~300, speech p90 ~3,800).
- Agent "Nudge quiet callers / hang up after unanswered nudges" ends a silent session; the harness must keep talking.
- **Spike 2 PASS:** tool called on **12/12 + 6/6 + 6/6** seller turns across 4 calls, often twice per turn (ASR finalises on a pause → partial utterance, then the full one).
- **Spike 4:** the tool receives the seller's words **in Devanagari**, verbatim (e.g. "अभी बिजी हूँ यार, जल्दी बोलो क्या है।"), with `language: "hindi"`. ASR errors seen: "अब बोट हो क्या", "अभी जी हूं यार". Cue matching needs Devanagari + Unicode NFD normalisation (nukta ज़).
- **Spike 3 PASS (stub classifier):** when the tool returned the mode, the agent followed the directive. rushed → 11–13 words + callback offer ("कोई बात नहीं, आप बताइए मैं आपको कब call back करूँ?"); confused → one simple idea + "क्या आप समझ पाए?"; bot_question → "हाँ जी, मैं IndiaMART का AI assistant हूँ". Caveat: in one neutral-mode run the agent also gave a short callback reply by itself; in another it gave a 30-word pitch, so prompt-only behaviour is inconsistent and an ON/OFF comparison is needed for attribution.
- **Reply latency after the seller stops (ASR endpoint + tool + LLM + TTS): median ~2.1 s, range 1.2–3.5 s** (stub classifier, i.e. without Jev latency). No no-tool baseline measured yet.

## Jev latency breakdown (2026-10-07 ~09:20, office laptop on VPN, IPv4)
- Network to OpenRouter (Cloudflare DEL edge): GET round trip on keep-alive p50 **18 ms**; curl TCP connect 15–26 ms, TLS done 46–95 ms.
- Decisions API, 1 question, **new connection per call: p50 760 ms**; **keep-alive: p50 491 ms**; 6 questions on keep-alive: p50 482 ms (question count barely matters).
- OpenRouter generation stats for a 6-question call: `latency: 315` ms, provider TypeSafe, 979 prompt tokens, $0.000041.
- Interpretation: ~18 ms local network + ~150 ms OpenRouter overhead + ~315 ms TypeSafe upstream (network + inference). The research's 108 ms was a direct-to-TypeSafe call from the demo author's machine, location unknown (likely US). The earlier 799 ms p50 here was inflated by per-call TLS setup.
- TypeSafe direct endpoint (api.typesafe.ai) is also behind Cloudflare (104.18.25.46); it isn't an allowed component under our rule (OpenRouter only).
