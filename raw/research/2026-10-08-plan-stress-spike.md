# Spike: plan stress test, plan delivery route, restarted replies (2026-10-08)

Code: `app/spike/plan_stress.py`. Results: `outputs/spike-plan-stress-20261008-040704.json`, `outputs/spike-plan-stress-20261008-040920.json`. Made-up sellers only.

## Design
- Conditions: **P** = plan in initial `agent_variables` AND re-sent by the signal server inside every per-turn `persona_directive`; **V** = plan ONLY in initial `agent_variables` (server returns plain directives, which overwrite `persona_directive` after the first tool call).
- Scenarios (5 seller turns each, Sarvam TTS seller): **A_hostile** (off-topic "who are you", "I'm not the owner", exact price demanded twice, then rush); **B_gujarati** (objection before the plan reaches it, price push, seller switches to Gujarati in Gujarati script, meeting + time in Gujarati); **A_coop** (cooperative, under V only; P was run earlier: 15/16).
- 2 runs per scenario × condition = 10 calls, 46 seller turns. Regex checks per turn + manual read of every reply.

## Results
- **P: 20/20 checks** (hostile + Gujarati). Off-topic question answered and steered back to the plan; "not the owner" → asks when owner is back; price demanded twice → never any amount (0/8 price turns had a number), redirects to the executive meeting; rush → "कोई बात नहीं, मैं आपको किस time दोबारा call करूँ?" (10 words); objection before its step → playbook answer then back to plan; Gujarati switch 2/2, meeting and confirmation stayed in Gujarati.
- **V: 23/28 checks; plan content degrades after the first tool call.** Seller-specific personalisation lost (A_coop step 2: 0/2 — generic "more buyer enquiries" instead of "you asked us to call back about PVC buyers in Indore"); B's "already have leads" playbook lost 0/2 (generic "convert leads better"); replies longer (price turns 31–37 words vs 22–26 under P); one off-plan line ("मैं सिर्फ एक AI assistant हूँ और मुझे exact prices नहीं पता"). Safety rules mostly held (no amounts) because they also live in the base prompt. One V fail (Gujarati meeting time) is a regex miss — the agent did ask for a time.
- **Language switch:** built-in Sarvam switch worked 6/6 (4 P + 2 V turns checked; agent continued in Gujarati script, used Gujarati numerals). On the switch turn the agent did **not** call our tool (tools=[] on 4/4 switch turns), so the switch log must capture language switches from the transcript/language field, not from the tool.
- **Lexicon false positive observed:** "Phir se pooch raha hoon, price batao…" was classified `confused` (cue "phir se") in 4/4 runs, the agent then added "क्या यह clear है?" — a real example of a false switch for the between-run reviewer.
- **Restarted/duplicated replies:** by manual read ~8 of 46 turns (~17%) show a restarted or duplicated segment in the transcript (e.g., "कोई बात नहीं, मैं आपको किस time दोबारा call करूँ कोई बात नहीं, मैं आपको किस time दोबारा call करूँ?"; two Gujarati openings back to back). The automatic detector caught only 3 (it misses full-sentence repeats). On these turns a tool call often arrived *before* the seller finished (negative offsets, e.g. −0.7 s, −2.0 s) and again after, and several turns show 2–4 separate agent speech bursts. It also happened on the Gujarati switch turn where no tool was called. Working hypothesis: the agent ends the seller's turn early at a mid-utterance pause (comma), starts replying, then restarts when the rest of the utterance arrives; the double tool call is a symptom, not the cause. Not yet confirmed (no audio review; endpointing settings untested).

## Implications
- The plan must be re-sent every turn (server keyed by call), or placed in an agent variable the tool response does not overwrite (needs an agent-config change: a separate `@call_plan` variable). Plan only at call start is not enough.
- Next tests: restart rate with seller audio without mid-sentence pauses vs with; Sarvam endpointing/interruption settings; a separate non-overwritten plan variable.
