# Adversarial review: persona-e2e-plan.md + persona-skill-design.md

Date: 2026-10-10 (Day 2 of the hackathon; submission closes 23:59 today). Reviewer stance: hackathon judge + senior ML/agent architect.
Judged against `raw/hackathon/2026-10-08-ps04-persona-design-problem-doc.md` and `raw/hackathon/2026-10-07-hackathon-deck-problem-statements.md`. The team decisions dated 2026-10-08 to 2026-10-10 are treated as binding. Only contradictions with them, and mitigations they need, are flagged.

## Verdict

**FAIL as written.** The design itself is mostly sound and fits the binding decisions:
- script facts, then agent judgement under gates;
- a fixed Sarvam template filled by variables;
- an in-Sarvam keyword switcher with a switch log;
- learning between runs.

As a plan for a submission due tonight, it fails for five reasons:
1. It has nine serial build steps, and the code exists only for the builder and an untested `facts.py`. The five deliverables due tonight are not in the plan: demo video, one slide, skills.md, README and Sarvam agent ID.
2. The live-switch demo depends on a phone number that we do not have.
3. The persona spec schema leaves out fields that PS04 requires: accent, empathy, escalation rules, guardrails, a real objection playbook, and confidence and evidence strength for each choice.
4. Nothing checks the words that the frontier model writes and Sarvam speaks word for word. That covers the identity line, banned titles, numbers and prices, and gender agreement.
5. Several "proven" Sarvam assumptions are not proven: Jinja blocks, undefined variables, and the starting language.

The learning loops do not close in the demo. There is no captured outcome, no gold set and no control arm. Thompson credit is wrong once the agent selects and amends.

All of these can be fixed today if the scope is cut to the critical path in finding B1. With the Blocker fixes and the top Majors, this becomes PASS WITH FIXES.
